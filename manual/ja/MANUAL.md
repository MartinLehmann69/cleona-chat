## 1. Cleona Chat とは？

### あなたのメッセンジャー、あなたのデータ

Cleona Chat は、中央サーバーをまったく使わずに動作するメッセンジャーです。あなたのメッセージは、あなたの端末から相手の端末へ直接届きます――会社の本部も、クラウドも、データセンターも経由しません。途中で別の端末が手助けするときも、暗号化されたパケットを転送するだけです。そもそも間に介在する会社がないので、どの企業もあなたのメッセージを読んだり、保存したり、引き渡したりすることはできません。

### アカウント不要、電話番号不要

Cleona では、登録に電話番号もメールアドレスも必要ありません。あなたのアイデンティティは、初回起動時にあなたの端末上で自動的に生成される暗号鍵ペアで成り立ちます。つまり、あなた自身が連絡先を教えない限り、誰も電話番号やメールアドレスからあなたを見つけることはできません。

### 未来に強い暗号化

Cleona は、いわゆるポスト量子暗号を使っています。つまり、将来の量子コンピューターでもあなたのメッセージを解読できないということです。詳細を理解する必要はありません――大切なのは、あなたの通信が現在の技術水準において最善の形で守られているということだけです。

### サーバーなしでどう動くのか？

Cleona のネットワークは、利用者の端末だけで構成されます。各端末がノードであり、あるノードが他より重要になることはなく、各ノードは自分の隣人だけを知っています。このネットワークを特別にするのは、4つの点です。

- **固定の拠点がない。** アプリの中にサーバーアドレスは一切書かれておらず、ネットワークはどの単一ノードにも依存しません。Cleona を止めるために遮断できるものは何もありません。
- **即時。** あなたのメッセージは、送信した瞬間に動き出します。何らかのタイミングも、何か別のものも待ちません。
- **並行するカモフラージュ。** あなたの端末は常に小さなカバーパケットを送信し続け、外からはあなたが本当につっている瞬間が分からないようにします。どのメッセージもこれに依存しません――カバートラフィックはただ並行して走るだけです。
- **名前ではなくコード。** メッセージを転送する者は、毎日変わるコードしか見ません。通常は、彼らの誰も送信者と受信者を同時に知りません。例外は第14章にあります。

**3つの経路を、すべて同時に。** メッセージを送信するとき、Cleona は経路を次々に試すのではなく、適合するすべての経路を一度に試します。相手が受信を確認した瞬間に、残りは中止されます。

1. **同じネットワーク内:** 同じ Wi-Fi にいるなら、メッセージは直接向こう側へ渡ります。
2. **固定の隣人経由:** インターネットでは、あなたの端末がメッセージを自分の固定の隣人に渡します。その隣人が、相手の固定の隣人（最大3つ同時）へ転送し、そのうちの1つが配達します。
3. **メールボックス:** 相手がオフラインのとき、Cleona はメッセージを暗号化した上で3人の隣人に預けます。そこに最大7日間留まります。相手がオンラインに戻ると、取りに行きます。

**どうやってネットワークに入るのか？** アプリの中にサーバーアドレスは書かれていません。あなたの入口は、最初の連絡先から得られます。その相手の招待には、あなたの端末が最初の隣人を見つけるためのアドレスが含まれています。同じ Wi-Fi では、Cleona の端末同士が自分たちで見つけ合います。そこから先は、あなたの端末は隣人に出会うたびにさらに多くの隣人を知っていきます。

### プラットフォーム

CleonaはAndroid、iOS、macOS、Linux、Windowsで利用できます。パソコンとAndroidでは、メッセージと通話は数秒以内に届きます。iPhoneでは、アプリを開いている間はこれが当てはまります。開いていないとき、iOSはアプリを時々短時間だけ起こします。いつ起こすかはiOSが決めます。Cleonaはそのとき、あなたのために保管されていたものをすべて受け取り、アプリのアイコンに数字付きの通知を表示します。アプリを開いていないiPhoneには通話は届きません。これはAppleのルールであり、Cleonaの欠陥ではありません。

## 2. はじめに

### アプリをインストールする

**Android:**
1. Cleona のウェブサイトまたは GitHub Releases から APK ファイルをダウンロードします。
2. スマートフォンでそのファイルを開きます。必要に応じて、提供元不明のアプリのインストールを許可します（Android が自動で尋ねます）。
3. 「インストール」をタップし、インストールが完了するまで待ちます。

**iOS:**
1. iPhone で TestFlight の招待リンクを開きます。
2. 「インストール」をタップします。TestFlight は、ベータアプリを配布する Apple の公式の手段です。
3. インストール後、Cleona はホーム画面に表示されます。

**macOS:**
1. Cleona のウェブサイトまたは GitHub Releases から DMG ファイルをダウンロードします。
2. DMG を開き、Cleona をアプリケーションフォルダにドラッグします。
3. 初回起動時、macOS が、識別された開発者のアプリを開くかどうか尋ねることがあります――これを承認します。

**Linux (Ubuntu/Debian):**
1. Cleona のウェブサイトまたは GitHub Releases から .deb ファイルをダウンロードします。
2. ダブルクリック、またはターミナルでインストールします: `sudo dpkg -i cleona-chat-beta_VERSION_amd64.deb`
3. アプリケーションメニューから、またはターミナルで `cleona-chat-beta` を実行して Cleona を起動します。

**Linux (Fedora/openSUSE):**
1. Cleona のウェブサイトまたは GitHub Releases から .rpm ファイルをダウンロードします。
2. 次のコマンドでインストールします: `sudo dnf install cleona-chat-beta-VERSION-1.x86_64.rpm`
3. アプリケーションメニューから、またはターミナルで `cleona-chat-beta` を実行して Cleona を起動します。

**Linux (すべてのディストリビューション -- AppImage):**
1. Cleona のウェブサイトまたは GitHub Releases から .AppImage ファイルをダウンロードします。
2. ファイルを実行可能にします: 右クリック、プロパティ、実行可能、またはターミナルで `chmod +x cleona-chat-beta-VERSION-x86_64.AppImage`
3. ダブルクリック、またはターミナルで起動します: `./cleona-chat-beta-VERSION-x86_64.AppImage`

これらのパッケージ名はベータ版のものであり、ベータ版は現在唯一公開されているバージョンです。その名前は `cleona-chat-beta` です。

**Windows:**
1. Cleona のウェブサイトまたは GitHub Releases からインストーラーをダウンロードします。
2. インストールファイルを実行し、指示に従います。
3. スタートメニューまたはデスクトップのショートカットから Cleona を起動します。

### アイデンティティを作成する

初回起動時、Cleona はあなた用の新しいアイデンティティを自動的に作成します。表示名を設定できます――それは連絡先が見る名前です。この名前はいつでも変更できます。

### シードフレーズを書き留める――すべての中で最も重要なこと

アイデンティティを作成した後、Cleona は24個の単語を表示します。それがあなたの**シードフレーズ**――あなた専用の復元鍵です。

**この24個の単語を紙に書き留め、安全に保管してください。**

なぜこれがそれほど重要なのでしょうか？

- スマートフォンが壊れたり、紛失したり、盗まれたりした場合、この24個の単語で、新しい端末にアイデンティティ全体を復元できます。
- シードフレーズがなければ、もう元に戻る道はありません。「パスワードを忘れた」ボタンも、アカウントを取り戻してくれるサポートも存在しません――そもそもサーバー上にアカウントがないからです。連絡先も、何人いようとあなたのアイデンティティを復元することはできません。同じアイデンティティを持つ2台目の端末は、今後のバージョンで使えるようになります（第11章を参照）。
- シードフレーズを絶対に他人に渡さないでください。この単語を知る者は、あなたになりすますことができます。

24個の単語は、後で再度読みたい場合、設定の「バックアップ」→「回復フレーズ表示」からも確認できます。その際、Android では画面ロックで確認します。

### 最初の連絡先を追加する

誰かとチャットするには、まずその人を連絡先として追加する必要があります。そのための方法はいくつかあります――すべて、次の節で説明します。

## 3. 連絡先

### あなたの招待

Cleona では、連絡先は招待を通じてのみ生まれます。あなたの招待は、初回起動時からそこにあります――インターネットなしで、あなたの端末が隣人をまだ1つも見つけていないうちから。自分のアイデンティティ詳細ページ（上部のバーにある自分の名前をタップ）で見つかります。

招待は、まったく同じ内容を含む2つの形式で利用できます。

- 相手がそばにいるときは**QR コード**として、そして
- メール、SMS、または別のメッセンジャーで送る**テキスト行**として。

招待に電話番号や、名簿上の名前は含まれません。含まれているのはあなたの公開鍵と、相手があなたやあなたの隣人に届くためのアドレスです。そのため、新しく Cleona をインストールした人にとって、あなたの招待はネットワークへの入口にもなります。

### QR コードをスキャンする（推奨）

直接会うときは：

1. 相手に、あなたの招待の QR コードを見せます。
2. 相手がプラスボタンをタップし、「QR コードをスキャン」を選んで、カメラをあなたの画面に向けます。これはパソコンのウェブカメラでも機能します。
3. リクエストはあなたに届き、**自動的に承認されます**――あなたが自分でコードを見せたばかりだからです。

QR コードは1回限り有効です。最初の有効なリクエストが承認されると、招待は消費済みになります。QR コードは最も安全な方法です。このやり取りでは、誰と連絡先を交換しているのかを正確に把握できるからです。

### NFC（スマートフォン同士を合わせる）

両方の端末が NFC に対応している場合：

1. 両者とも連絡先追加機能を開きます。
2. スマートフォンの背面同士を合わせます。
3. 招待が転送され、自動的に承認されます。

NFC も QR コードと同様に高い安全性を提供します。物理的にそばに立っていないと交換が成立しないからです。

### テキスト行を送る

直接会えないときは：

1. 自分の招待を開き、テキスト行をコピーします。
2. あなたを追加してもらう人に、メール、SMS、または別のメッセンジャーで送ります。
3. 相手は Cleona の連絡先追加ダイアログにその行を貼り付けます。
4. リクエストはあなたの側の**「リクエスト」**に表示されます。ここでは**自動的に承認されません**：あなた自身が判断します。途中で誰がその行を読んだか分からないからです。

### 連絡先リクエストを承認する

届いたリクエストは、まだ連絡先を生み出しません。それはあなたにひとつの問いを提示し、**「リクエスト」**タブに表示されます。そこで名前と検証レベルを確認し、選ぶことができます。

- **承認**――ここではじめて、その人があなたの連絡先になります。
- **拒否**――リクエストは破棄されます。
- **ブロック**――その人はこれ以上リクエストを送れなくなります。

### 固定の隣人として使わない

連絡先のメニューに**「固定の隣人として使わない」**というスイッチがあります（既定値：オフ）。これをオンにすると、この連絡先はあなたのメッセージを転送せず、そのためあなたがいつメッセージを送信・受信するかも知りません。これは、身の回りから危険が及ぶ場合を想定した設定です。

未知の相手（連絡先でも共通グループのメンバーでもない者）からは、そうしたリクエスト以外、Cleona は何も通しません――メッセージも、通話も、ファイルも。そして、そのリクエストすら、送信者があらかじめ小さな計算課題を解いた場合にのみ届きます。これが大量スパムを高コストにします。

### 検証レベル

Cleona は、連絡先のアイデンティティがどの程度確かに確認されているかを表示します。

| レベル | 意味 |
|-------|-----------|
| 未検証 | つながってはいるが、本当に正しい人物が背後にいることを確認するものは何もない。 |
| 確認済み | 鍵交換は成功し、暗号化して通信できる。 |
| 検証済み | 直接会って、カメラのスキャンまたは NFC で接続した。 |
| 信頼済み | この連絡先を、明示的に信頼に足るものとしてマークした。 |

「検証済み」は、直接会っての交換にのみ存在します。チャットやメールで届いた招待は、同じデータを含んでいても、このレベルに決して到達しません。

連絡先の鍵が予告なく変わった場合、Cleona は「未検証」にリセットします。これにより、誰かが気づかれずにあなたの連絡先になりすますのを防ぎます。

## 4. メッセージ

### テキストの送信と受信

下の入力欄にメッセージを入力し、Enter または送信ボタンを押すだけです。メッセージは、端末を出る前に自動的に暗号化されます。

届いたメッセージはチャットの履歴に表示されます。

### メッセージにつく記号の意味

| 記号 | 意味 |
|---------|-----------|
| 時計 | メッセージは作成されたが、まだどの経路もそれを運んでいない。 |
| チェック1つ | メッセージは配信中。メールボックスで相手を待っている間もこれに当てはまる。 |
| チェック2つ | 配信済み：相手の端末が受信を確認した。 |
| 警告記号 | 14日間、どの経路もメッセージを届けられなかった。タップして再送する。 |

**オフラインはエラーではない。** 相手に届かない場合、メッセージはチェック1つのまま、取りに行かれるまで待機します――失われるわけではありません。あなたの端末自身が接続を持っていない場合、メッセージは時計のまま留まり、再び経路ができた時点で自動的に送信されます。警告記号が表示されるのは、メッセージが14日間どの経路も見つけられなかったときになってからです。そのとき、再送できます。

これはアプリを開いていないiPhoneにも当てはまります。メッセージは、iOSがアプリを短時間起こすか、相手がそれを開くまで、メールボックスで待ちます。他の端末より時間がかかることがあります。

チェック2つは、受信者自身が受信を確認した場合にのみ存在します。この受信確認は暗号化され署名されています――途中の誰も、配信を装ってこれを偽造することはできません。

### 画像、動画、ファイルを送る

いくつかの方法があります。

- 入力欄の**クリップアイコン**：これをタップして、ギャラリーやファイルシステムからファイル、画像、動画を選びます。
- **ドラッグ＆ドロップ**（デスクトップ）：ファイルをチャットウィンドウにドラッグするだけです。
- **クリップボードから貼り付け**（デスクトップ）：画像をコピーし、チャットに貼り付けます。

小さなファイル（256 KB 未満）はメッセージの中に直接同封されて届きます。大きなファイルは断片に分割され、誤り訂正が付与されるため、一部の断片が失われても問題ありません。両者ともオンラインなら、隣人を経由してストリーミングされます。そうでない場合は、常に到達可能な端末に預けられ、相手が取りに行くまで留まります。

256 KB 以上のファイルは、送信前に Cleona がファイルごとにあなたに尋ねます。大きなファイルは、あなたのメッセージと同じ経路を通ることができません。その内容は暗号化されたままですし、相手もあなたのインターネットアドレスを知りません。しかし転送は外からは1つの出来事として見え、それを転送または保管するよその端末は、誰がアップロードし、誰が取りに行くかを見ます。あなたの同意は、その1つのファイルだけに有効です。

### 音声メッセージ

1. 入力欄のマイクボタンを長押しします。
2. メッセージを話します。
3. ボタンを離してメッセージを送信します。

端末で音声認識が有効な場合（設定を参照）、あなたの音声メッセージは自動的にテキストに書き起こされます。相手には録音と書き起こされたテキストの両方が表示されます。

### メッセージに返信する（引用）

特定のメッセージに返信するには：

1. メッセージの横にある三点メニューを開きます。
2. 「返信」を選びます。
3. 入力欄の上に、引用されたメッセージを含むバナーが表示されます。
4. 返信を書いて送信します。

引用されたメッセージはあなたの返信に表示され、関係が明確になります。

### メッセージを編集・削除する

- **編集：** メッセージの三点メニューから「編集」。テキストを変更して再送します。相手にはメッセージが編集されたことが表示されます。編集は送信後15分以内に行えます。
- **削除：** メッセージの三点メニューから「削除」。メッセージはあなたと相手の両方から削除されます。自分のメッセージはいつでも削除できます――削除に時間制限はありません。

### 絵文字リアクション

返信を書く代わりに、メッセージに絵文字でリアクションできます。

1. 三点メニューを開くか、メッセージを長押しします。
2. クイック選択から絵文字を選ぶか、絵文字ピッカーを開いて全選択肢から選びます。
3. あなたのリアクションがメッセージの下に表示されます。

### テキストをコピーする

メッセージの三点メニューから、メッセージのテキストをクリップボードにコピーできます。

### メッセージを検索する

チャットウィンドウの上部に検索機能があります。検索語を入力すると、Cleona は現在のチャット内のすべての一致箇所を表示します。矢印キーで一致箇所の間を行き来できます。

さらに、ホーム画面にはタブをまたぐ検索フィルタがあり、すべての会話をひとつの語で検索できます。

### リンクプレビュー

リンクを送信すると、Cleona は自動的にプレビュー（タイトル、説明、プレビュー画像）を生成します。このプレビューはあなたの端末で作成され、一緒に送信されます――相手がリンク先のウェブサイトに接続する必要はありません。

届いたリンクをタップしたとき何が起きるかは、設定の「リンクの開き方」で選びます。「通常」、「シークレットを優先」（端末がシークレットウィンドウを開けないところでは、リンクは通常どおり開きます）、または「毎回確認」です。

## 5. グループ

### グループを作成する

1. 「グループ」タブに切り替えます。
2. プラスボタンをタップします。
3. グループに名前を付けます。
4. 招待したい連絡先を選びます。
5. 「作成」をタップします。

招待された連絡先には通知が届き、グループに参加できます。

### グループメッセージが守られる仕組み

最大16人までのグループでは、Cleona は各メッセージを各メンバーに個別に送信します――それぞれそのメンバー専用に暗号化され、まるで各人に別々のメッセージを書いたかのように。グループメッセージのチェックは、最も進んでいないメンバーの状態を示します。

グループが16人を超えると、共通の鍵を使うようになります。鍵は毎日変わり、メンバーが脱退または除去されると新しく引き直されます。新しいメンバーは、参加した時点からしか読めません。この場合チェックは、各メンバーの状態ではなく、メッセージがネットワークに預けられたことを示します。グループが12人以下になると、個別送信に戻ります。

### グループとチャンネルでの画像

グループまたはチャンネルの設定で、「画像を常に読み込む」により、画像をすぐに読み込むか、タップして初めて読み込むかを決められます。

### メンバーを招待する

作成後も、さらに連絡先を招待できます。

1. グループ情報を開きます（グループ一覧の三点メニュー、またはグループチャットの上部バー）。
2. 「招待」をタップします。
3. 追加したい連絡先を選びます。

### ロール

各グループには3つのロールがあります。

- **オーナー（Owner）：** 完全な権限を持ちます。メンバーの追加・削除、管理者の任命、グループの管理ができます。オーナーは自分の地位を別のメンバーに譲渡することもできます。
- **管理者（Admin）：** メンバーの削除と管理の補助ができます。
- **メンバー（Member）：** メッセージの読み書きができます。

### グループを抜ける

1. グループ一覧の三点メニューを開きます。
2. 「抜ける」を選びます。
3. 判断を確認します。

グループを抜けても、これまでのあなたのメッセージは他のメンバーに見えたまま残ります。

## 6. 公開チャンネル

### チャンネルとは？

チャンネルは、Cleona のネットワーク内の公開ディスカッションホームです。グループとは異なり、ここでは誰でも招待なしに読むことができます。投稿できるのはオーナーと管理者だけです――購読者は読みます。

### チャンネルを見つけて参加する

1. 「チャンネル」タブに切り替えます。
2. 「検索」のタブを開きます。
3. 利用可能なチャンネルを名前やテーマで検索します。
4. チャンネルをタップし、次に「購読」をタップします。

チャンネルは言語で絞り込めます。一部のチャンネルは「成人向け」とマークされています――これらは、プロフィールで18歳以上であることを確認した場合にのみ表示されます。

### 自分のチャンネルを作成する

1. 「チャンネル」タブに切り替えます。
2. プラスボタンをタップします。
3. チャンネル名を入力します（ネットワーク全体で一意でなければなりません）。
4. 言語と、チャンネルを公開にするか非公開にするかを選びます。
5. 任意で、説明と画像を追加します。
6. 「作成」をタップします。

公開チャンネルでは、コンテンツを「成人向け」と分類するかどうかを設定できます。

### コンテンツを報告する

公開チャンネルで不適切なコンテンツを見つけた場合、報告できます。Cleona は分散型モデレーションシステムを使います。報告はネットワーク内からランダムに選ばれたメンバーによって評価されます（一種の「陪審」）。違反が認められると、チャンネルには警告が出されます。違反が繰り返されると、検索インデックスで降格されるか、ブロックされます。

### システムチャンネル

Cleona には組み込みのシステムチャンネルが2つあります。

- **Bug Log:** Cleona がエラーを検出すると、エラーレポートを送るかどうか尋ねます。その前に、何が公開されるかを正確に確認できます。これらのレポートは Bug Log チャンネルに集まり、コミュニティが確認できます。レポートには名前も会話の内容も含まれず、仮名だけが入ります。ベータ版では、開発者が問い合わせられるように、さらにあなたの識別子（User-ID）が記されます。プレビューダイアログと明示的な同意の上で、手動でログレポートを送ることもできます。
- **Feature Requests:** ここでは、利用者が機能の要望を投稿し、既存の提案に投票できます。提案は得票数で並び替えられます。

各パソコンはシステムチャンネルごとに最大25 MB、各スマートフォンは最大5 MBを保持します。満杯になると、最も古いものから先に消えていきます――あなた自身がすでに見たものが消されることはありません。

## 7. 通話

### 音声通話を始める

1. 通話したい連絡先のチャットを開きます。
2. 上部バーの電話アイコンをタップします。
3. 相手が通話に出るまで待ちます。

通話中は、タイムラインと通話時間が表示され、ミュートとスピーカーにアクセスできます。

通話を終えるには、赤い終了ボタンをタップします。

「つながらない」と表示された場合、相手の端末が今は到達できない状態です。たとえばアプリを開いていないiPhoneです。代わりにメッセージを送ってください。

### ビデオ通話を始める

1. 連絡先のチャットを開きます。
2. 上部バーのカメラアイコンをタップします。
3. あなたの映像は小さいウィンドウに、相手の映像は大きな領域に表示されます。

通話中にインカメラとアウトカメラを切り替えられます。

### 着信通話

誰かがあなたに通話をかけると、発信者の名前を含む通知ウィンドウが表示されます。次の選べます。

- **出る**――通話が始まります。
- **拒否**――発信者に通知されます。

通話中に新しい着信があっても、着信音は鳴りません。代わりに「不在着信」というメッセージが届きます。応答しなかったグループ通話も同様です。そのメッセージはグループチャットに表示されます。

現在表示されていないあなたのアイデンティティの1つに誰かが通話をかけた場合も、着信音は鳴ります。通話画面には、あなたのどのアイデンティティが呼ばれているかが表示されます。

iPhoneでは、アプリを開いている間だけ着信音が鳴ります。開いていないときにあなたに電話をかけた相手には、10秒後に「つながらない」と表示されます。アプリを開くとすぐ、不在着信のメッセージが見つかります。

### グループ通話

複数人が同時に参加するグループ通話も行えます。通話は知的な転送ツリーで編成されるため、すべての参加者が他の全員と直接つながっている必要はありません。すべての通話は終始暗号化されています。

どのグループメンバーでもグループ通話を開始できます。互いに連絡先でない2人の参加者は、相手のインターネットアドレスを決して見ません。その2人の音声と映像は、両方と連絡先である参加者を経由します。そのような参加者がいない場合、2人はつながらず、タイルには「通話に共通の連絡先がいない」と表示されます。転送がいっぱいになっているときは、音声は残り、その2人の映像は省かれます。

### 通話の暗号化

すべての通話は、通話の期間だけ存在する使い捨ての鍵で暗号化されます。通話を終えると、これらの鍵は直ちに削除されます。誰も、過去の通話を事後的に復号することはできません。

正直言って：通話は、可能な限り端末同士で直接行われます。話すときはわずかな遅延でも邪魔になるからです。そのため、メッセージとは異なり、通話ではインターネットプロバイダーが、あなたがどのインターネットアドレスとつながっているかを見ることができます。話している内容は見えません。

通話では、連絡先もあなたのインターネットアドレスを見ます。特定の連絡先についてそれを望まない場合は、その連絡先のメニューで「通話を許可」をオフにします（既定値：オン）。後からオフにしても、すでに見られたアドレスはその連絡先に知られたまま残ります。

## 8. カレンダー

Cleona には組み込みのカレンダーがあり、暗号化され完全に分散して動作します――クラウドサービスなしで。

### 表示

カレンダーには5つの表示があります：日、週、月、年、そしてタスク表示。カレンダー画面上部のタブで切り替えます。

### 予定を作成する

時間枠をタップするか、追加ボタンを使って新しい予定を作成します。タイトル、日付、時刻、場所、メモを入力できます。予定はあなたの端末に暗号化されて保存されます。

### 繰り返しの予定

予定は毎日、毎週、毎月、毎年で繰り返せます。パターンを調整でき（例：隔週の火曜日、毎月1日）、終了日または繰り返し回数を設定できます。

### 連絡先を招待する

予定の作成・編集時に、Cleona の連絡先を招待できます。相手には暗号化されたカレンダー招待が届き、参加・不参加・未定で返答できます。予定の変更は、招待した全員に自動的に送信されます。

### 空き/予約状況の表示

予定の詳細を明かさずに、自分の空き状況を連絡先と共有できます。プライバシーレベルは3つあります：詳細すべて、時間枠のみ、または非表示。既定値を設定し、連絡先ごとに上書きできます。

### リマインダー

予定にはリマインダーを設定でき、予定開始前にシステム通知を出します。必要に応じてリマインダーをスヌーズできます。

### 外部カレンダーとの同期

Cleona は外部のカレンダーサービスと同期できます。

- **CalDAV** -- 任意の CalDAV 互換サーバーと接続します（Nextcloud、Radicale など）。
- **Google カレンダー** -- Google Calendar API と安全な OAuth2 認証で同期します。
- **ローカル CalDAV サーバー** -- Cleona はあなたの端末でローカル CalDAV サーバーを起動でき、デスクトップのカレンダーアプリ（Thunderbird、Outlook、Apple カレンダー、Evolution）が Cleona のカレンダーと同期できます。
- **Android システムカレンダー** -- Cleona の予定を、Android 端末の組み込みカレンダーアプリに転送できます。
- **ICS ファイル** -- 標準の iCalendar 形式で予定をインポート・エクスポートします。

### PDF 書き出し

任意のカレンダー表示（日、週、月、年）を PDF ドキュメントとして印刷または書き出せます。

## 9. アンケート

任意のチャットやグループでアンケートを作成し、意見を集めたり日程を計画したりできます。

### アンケートの種類

Cleona は5種類のアンケートに対応します。

- **単一選択** -- 参加者が1つの選択肢を選びます。
- **複数選択** -- 参加者が複数の選択肢を選べます。
- **日程アンケート** -- 全員に合う日時を見つけます。各参加者が日時を「可能」「たぶん」「不可」でマークします。
- **スケール** -- 数値スケールで評価します（例：1〜5）。
- **自由記述** -- 参加者が自分自身の回答を書きます。

### アンケートを作成する

チャットを開き、アンケートアイコンをタップします（または添付メニューを使います）。アンケートの種類を選び、質問と選択肢を整えて、アンケートを送信します。チャット内にメッセージとして表示されます。

### 投票する

アンケートをタップして投票します。票はいつでも変更・取り下げできます。

### 匿名投票

アンケートは匿名投票に設定できます。有効にすると、票は暗号学的に匿名になり――誰も、アンケートの作成者でさえ、誰が何に投票したかを見ることはできません。票数はそれでも表示されます。

### 日程アンケートをカレンダーへ

日程アンケートが完了すると、当選した日時をワンタップでカレンダーの予定に変換できます。

## 10. 複数のアイデンティティ

### なぜ複数のアイデンティティなのか？

仕事と私生活を分けたいと考えてみてください――2つの電話番号を持つのと似ていますが、2台目のスマートフォンは不要です。Cleona では、1台の端末で複数のアイデンティティを使えます。各アイデンティティは独自の名前、独自のプロフィール画像、独自の連絡先、独自の会話を持ちます。

### 新しいアイデンティティを作成する

1. 上部バーに、現在のアイデンティティがタブとして表示されます。
2. アイデンティティのタブの右にあるプラス記号（+）をタップします。
3. 新しいアイデンティティの名前を入力します。
4. 完了――新しいアイデンティティが直ちに有効になります。

### アイデンティティを切り替える

上部バーのアイデンティティタブをタップするだけです。切り替えは瞬時です――待ち時間も、再読み込みもありません。

### すべてが同時に動く

重要な点：すべてのアイデンティティが同時に動いています。「仕事」と表示されている間も、「プライベート」のアイデンティティは引き続きメッセージを受け取ります。どのアイデンティティを選んでいても、何も見逃しません。

### アイデンティティ詳細ページ

現在アクティブなアイデンティティのタブをタップすると、詳細ページが開きます。ここで次のことができます。

- 連絡先用の QR コードを表示する。
- プロフィール画像を変更・削除する。
- プロフィール説明を追加する。
- 表示名を変更する。
- このアイデンティティ用のデザイン（スキン）を選ぶ。
- 不要になったアイデンティティを削除する。

### アイデンティティを削除する

アイデンティティを削除すると、連絡先に通知されます。アイデンティティと関連するすべてのデータが端末から削除されます。この操作は取り消せません。

## 11. 複数の端末

### 1つのアイデンティティ、1台の端末――当面は

今日、1つのアイデンティティは1台の端末で動きます。同じアイデンティティ用の2台目の端末は、今後のバージョンで使えるようになります。そのため、設定の「デバイス」→「デバイス管理」では「別のデバイスをペアリング」が「まだ使えない」と表示されています。

この機能が登場したら、すべての端末は対等で、メインの端末は存在しません。さらなる端末は24個の単語でセットアップし、既存の端末の1つが承認します。最大5台です。

今日、新しい端末で24個の単語を入力すると、引っ越しになります。アイデンティティは新しい端末で復元され、今までの端末はその後、アイデンティティを自分の側から削除します（第12章を参照）。

複数の端末では、今日は異なるアイデンティティを使えます（第10章）。

### アイデンティティの鍵を引き直す

誰かがあなたの鍵を手にしたのではないかと疑ったら、「デバイス管理」→「鍵のローテーション」で新しい鍵を生成できます。連絡先には通知され、開かれている招待は取り消されます。重要：この後、24個の単語だけでは古い鍵しか復元できなくなります。そのため、直後に新しい復元パッケージを作成してください。復元は、そのパッケージと一緒でなければできなくなります。

## 12. 復元

### シードフレーズを使う

端末を失くした場合や、新しくセットアップする場合：

1. 新しい端末に Cleona をインストールします。
2. 起動時に「復元」を選びます。
3. 24個の単語を入力します。
4. Cleona はそこから、あなたのすべてのアイデンティティを、以前と同じ鍵で再生成します。連絡先にとって、あなたは同じ人物です。

### 戻ってくるもの――戻らないもの

アイデンティティは24個の単語に宿りますが、連絡先と履歴は違います。戻ってくるのは、**復元パッケージ**によるネットワークへのアクセスです。あなたの端末は、小さな暗号化パッケージをネットワークに預けます。あなたの24個の単語だけがそれを見つけ、開けます。そこには、新しい端末が連絡先に再び届くために必要なものと、その間にネットワークであなた宛てに預かっていたものが書かれています。このために、どの連絡先もオンラインである必要はありません。

これまでのチャット履歴は、復元で戻ってきません。

復元パッケージは7日間生き、端末が動いている間は端末によって更新されます。設定で、いつまで有効かを見られます。7日を超えてどの端末も動いていなかった場合、復元パッケージは期限切れです。その場合も24個の単語はアイデンティティを復元しますが、連絡先は改めて招待し直さなければなりません。その間にネットワークであなた宛てに預かっていたものは失われます。

### 復元は引っ越し

今までの端末が後から、アイデンティティが別の場所で復元されたことを検出すると、端末はアイデンティティを――履歴とともに――自分の側から削除します。だからこそ、24個の単語を持つ者は、この方法であなたの端末からアイデンティティを引き取ることができます。すべての連絡先が戻るまで、アプリがあなたに思い出させます。「完了して鍵を更新」で、復元を自分で終わらせます。

### 誰も復元できないもの

これは重要であり、だからこそ明確に言っておきます。

- **あなた以外の誰も、あなたのアイデンティティを復元できません。** 開発者も、サポートも、連絡先さえも――何人いようと。合鍵も、あなたの鍵の一部が他人に預けられていることもありません。
- **24個の単語を失くし、もう端末が1台もないなら、あなたのアイデンティティは失われます。** その場合、新しく作り直し、連絡先を改めて招待するしかありません。

最善の保護：24個の単語を紙に書き留め、安全に保管してください。

## 13. 設定

設定には、右上の歯車アイコンからアクセスします。

### 通知と着信音

- 着信用に6種類の着信音から選べます。
- メッセージ通知音を設定します。
- Android 端末では、振動を追加でオン・オフできます。
- **「すべてミュート」**は、この端末上で、どのメッセージも鳴らず、振動せず、通知されないようにします――すべてのアイデンティティに対して。通話は引き続き鳴ります。
- **「おやすみ時間」**は、アイデンティティごとに開始時刻と終了時刻で設定します。この間、そのアイデンティティのメッセージは鳴らず、振動せず、通知されません。メッセージ自体はそれでも届きます。
- **「内容のない通知」**（既定値：オフ）は、メッセージ、招待、リマインダーが届いたことだけを示します――送信者、名前、テキストはありません。通話は引き続き名前を表示します。
- 起動後にまとめて届いたものは、Cleona は1つのまとめ通知（「2つの会話で5件の新しいメッセージ」）で知らせます。それ以降に届くものは1つずつ。メッセージ通知をタップすると、別のアイデンティティの会話でも、その会話が開きます。

### デザイン（スキン）

Cleona は10種類のデザインを提供します：Teal、Ocean、Sunset、Forest、Amethyst、Fire、Storm、Slate、Gold、Contrast。Contrast デザインは最高のアクセシビリティレベル（WCAG AAA）を満たし、視力が制限されている場合に特に読みやすいです。

各アイデンティティは独自のデザインを持てます。デザインはアイデンティティ詳細ページ（アクティブなアイデンティティタブをタップ）で変更します。

さらに、設定の「外観」で、ライト・ダーク・システムテーマを切り替えられます。

### 言語を変更する

Cleona は34言語で利用でき、右から左へ書く言語（例：アラビア語、ヘブライ語）も含まれます。設定の「言語」で言語を変更します。

### メディアのアーカイブ

自宅にネットワークストレージ（NAS）や共有フォルダがある場合、Cleona はメディアを自動的にそこへ退避できます。SMB、SFTP、FTPS、WebDAV に対応しています。

段階的ストレージの仕組み：
- 最初の30日間：すべてが端末に残ります。
- 30日後：プレビュー画像が端末に残り、オリジナルはアーカイブされます。
- 90日後：小さなプレビュー画像だけが端末に残ります。
- 1年後：プレースホルダだけが残り、オリジナルは安全にアーカイブに置かれます。

アーカイブされたメディアはいつでもタップして取り寄せられます――ただし自宅のネットワークに接続していることが条件です。特に重要なメディアはピン留めでき、退避されなくなります。

「ストレージ予算」では、何 MB のメディアを端末に残すかを設定します（既定値：スマートフォンで100 MB、パソコンで2 GB）。満杯になると、ピン留めされていない最も古いメディアから先にアーカイブされます。オリジナルは、アーカイブに確実に収まった場合にのみ削除されます――テキストメッセージは常に保持されます。

### 音声メッセージの書き起こし

有効にすると、あなたの音声メッセージが端末上でローカルにテキストへ変換されます（オープンソースモデル Whisper 使用）。書き起こされたテキストは録音と一緒に相手へ送られます。書き起こしは完全にあなたの端末上で行われます――外部サービスにデータは送られません。

どのモデル（tiny、base、small）をダウンロードするかは、端末について1度だけ設定します。言語（自動または固定）はアイデンティティごとに設定します。

### 自動ダウンロード

メディアを自動的にダウンロードするサイズのしきい値を設定できます。例えば、画像は自動で読み込みつつ、大きな動画は手動で判断できます。

### デバイス

「デバイス」→「デバイス管理」では、この端末が表示されます。別のデバイスのペアリングは、今後のバージョンで使えるようになります（第11章）。

### ネットワーク

Cleona は機能するためにネットワーク設定を必要としません。ネットワークのスイッチは3つあります。

- **ルーターでのポート開放**（既定値：オン）。Cleona は自分のルーターに、Cleona 用の扉を開けるよう依頼します。これが成功すると、あなたの端末は他者からより良く到達可能になり、ネットワークに貢献します。このとき Cleona はあなたのルーターとだけ話し、インターネットとは話しません。
- **公開アドレス登録**（既定値：オン）。あなたの端末の隣人がまだ少なすぎる場合、公開の名簿（Nostr）でさらなる入口を探し、自身も良く到達可能ならそこに自分を登録します。その登録に含まれるのはアドレスだけで、名も連絡先もありません。これをオフにすると、あなたの端末は隣人を、招待とローカルネットワーク、そしてすでに知っている隣人からだけ見つけるようになります。
- **Wi-Fi でカバーパケットを減らす**（既定値：オフ）。Wi-Fi または有線では、空のカバーパケットをオフにできます。ただしそのとき、あなたがいつつっているかが再び見えるようになります。モバイル回線にはこのスイッチはありません――そもそもモバイル回線では Cleona は1分あたり1つのカバーパケットしか送信しません。

カバートラフィック全体を止めることはできません。これは意図的なものです：常に動いていてこそ、あなたの端末のアクティビティは、あなたが今つっているかどうかを何も語らないからです。

3つのスイッチの上には**データセーバーモード**があります。モバイル回線では Cleona がそれを提案しますが、自動でオンにすることは決してありません。データを節約する代わりに、あなたの端末は外から見分けやすくなります。

その下では**「他の人のメディア用キャッシュ」**を設定します。あなたの端末は、他の人のメディアの暗号化された断片を、受信者に届くよう最大7日間保持します（既定値：スマートフォンで100 MB、パソコンで1 GB）。より小さいサイズにすると、その場所はすぐに解放されます――最も古い断片から順に。

## 14. セキュリティ

### ポスト量子暗号とは何か？

今日の暗号化は、通常のコンピューターには極めて解きにくい数学的問題に基づいています。量子コンピューターは、将来これらの問題のいくつかを素早く解ける可能性があります。ポスト量子暗号は、量子コンピューターにも耐える追加の手法を使います。

Cleona は両方の手法を組み合わせます：信頼性のために古典暗号を、未来への安全性のためにポスト量子手法を。これにより、今日と未来の脅威に対して同時に守られます。

個々のメッセージごとに、専用の鍵が生成されます。あるメッセージの鍵を攻撃者が解読できたとしても、それで他のメッセージを読むことはできません。

### なぜサーバーがない方が安全なのか

従来のメッセンジャーでは、あなたのメッセージはプロバイダーのサーバーを経由します。そこで暗号化されていても、プロバイダーはメタデータ（誰が、いつ、誰と、どのくらいの頻度で、どこから通信するか）にアクセスでき、裁判所の命令によりこれを引き渡さなければならない場合があります。

Cleona には、そうした中央の拠点がありません。すべてのメタデータが集まる場所も、あなたが誰か、誰を知っているかを照会できる名簿も存在しません。

### 誰が、あなたが誰かとついているのを見るのか？

暗号化は、あなたが**何を**書くかを守ります。同じくらい重要なのは、あなたが**誰と**、**いつ**ついているかを、どの単独の観察者も知ることができないことです。Cleona は次のようにこれを実現します。

- **インターネットでは決して直接。** あなたの端末がメッセージを相手のインターネットアドレスへ直接送ったら、プロバイダーがあなたが誰とついているかを見る可能性があります。だからインターネット上のメッセージは常に、あなたと相手の固定の隣人を経由します。
- **信頼する隣人。** あなたの固定の隣人は、可能な限り、あなた自身の連絡先の端末です――外から到達可能なものを最大3つ。1つ消えたら、別の連絡先が代わりに入ります。連絡先はサーバーのように買えませんが、ネットワークの任意のノードは買えます。まだ到達可能な連絡先がない場合、Cleona は別の隣人を使います。あなたの招待は、あなたの連絡先のいずれも名指ししないので、誰も招待から友人のアドレスを知ることはできません。
- **名前ではなくコード。** 隣人が見るのは名前でも識別子でもなく、コードだけです。それは正確にあなたたち両者に、一方向に、1日だけ有効です――翌日は別のコードになります。あなたの隣人は、パケットがどこから来たかは知っていても、最終的にどこへ行くかは知りません。相手の隣人は、どこへ行くかは知っていても、どこから来たかは知りません。通常は、途中の誰も両端を見ることはありません。
- **カバートラフィック。** あなたの端末は、不規則な間隔で隣人へカバーパケットを送り続けます。それらは本物のパケットと同じ大きさで、同じポートを通り、外からは区別できません。人が今つっているのか、端末がただ動いているだけかは、これでは分かりません。あなたのメッセージは決してカバートラフィックを待ちません――すぐに出発し、カバートラフィックはただ並行して走るだけです。

**カバートラフィックのコスト：** Wi-Fi では1日約13 MB。モバイル回線では Cleona は1分あたり1つのカバーパケットだけを送り、1日約1.7 MBです。モバイル回線での制限の理由はデータ量ではなくバッテリーです：パケットごとに通信モデムが起きるからです。

**Cleona が隠せないこと**――正直言って：

- **単一の**観察者は、誰が誰とついているかを見ません――あなたのプロバイダーも、途中のノードも。ただし**両端を同時に**監視する者、例えばあなたの回線と相手の回線を観察する国家や、両方の隣人を押さえる者は、時間をかけて紐付けできます：あなたの側でパケットが出て、間もなく相手の側でパケットが入る。これが十分に繰り返されると、つながりが浮かび上がります。
- カバートラフィックはこの紐付けを困難にしますが、防ぐことはできません。それは個々のメッセージを隠すのであって、量ではありません：非常に多く送る者は、自分の端末の総通信量を増やします。
- あなたの固定の隣人である連絡先は、あなたが**いつ**、**どれだけ**送信・受信するかを知ります――誰と、何をは知りません。危険が身の回りから来る場合、任意の連絡先をこれから外せます（第3章「固定の隣人として使わない」を参照）。
- 2人の新しい利用者が同じ1人の隣人だけを持つ場合、彼らのメッセージは正確にそのノードを経由し、そのノードは両端を見ます。どちらかがさらなる隣人を持てば、それは終わります。
- あなたの招待にはあなたのインターネットアドレスが含まれます。テキスト行を持つ者は、あなたがどこでオンラインかを見ます――信頼できる人にだけ渡してください。
- 転送する隣人は、2つのコードがパケットをやり取りしているのを見ます――その背後に誰がいるか、中に何があるかは見えません。
- 通話中の信号は、最初の隣人がちょうど応答しないとき、両端を見るノードを経由する場合があります。そのノードは、あなたたちが一緒に通話していることを知ります。
- 同意した大きなファイルは、それを転送または保管するコンピューターから、両端が見られます（第4章を参照）。
- 通話では、プロバイダーからの保護は適用されず、連絡先はあなたのインターネットアドレスを見ます（第7章を参照）。

### 相手がオフラインのとき、何が起きるのか？

1. Cleona は適合するすべての経路を同時に開始します：同じ Wi-Fi なら直接、インターネットでは2人の隣人経由――そして追加でメールボックス。
2. メールボックスのため、Cleona は暗号化されたメッセージを3人の隣人に預けます。2人が受信を確認した時点で、預けられたと見なされます。
3. Cleona はこの際、相手も覗きに来る隣人を優先します――まず、相手の招待が名指しする隣人です。
4. メッセージはそこで最大7日間待機します。相手が戻ると、取りに行き、あなたに受信を確認します。そのとき初めて、あなたにチェック2つが見えます。

メールボックスを空にできるのは相手だけです：取りに行って削除するには相手だけが持つ鍵が必要で、削除は相手が受信を確認した後に初めて行われます。隣人が見るのは、毎日変わる値の下の暗号化されたパケットだけです。

### 未知の相手は通さない

あなたの連絡先でも共通グループのメンバーでもない者から、Cleona は正確に2つのものだけを受け入れます：あなたの招待が1つでも開いている間の、あなたの公開鍵への問い合わせ、そして連絡先リクエストです。リクエストはあなたからの有効な招待を帯びていなければならず、送信者はあらかじめ計算課題を解いていなければなりません。それ以外――メッセージ、通話、ファイル――は、アプリに届く前に破棄されます。あなたの印刷した名刺だけを持つ者が、あなたに通話をかけたりはできない、ということです。共通グループのメンバーは、そのグループの中でしかあなたに届きません――グループメッセージとグループ通話だけで、個別には決して届きません。

### 検閲耐性

Cleona は遮断しづらく作られています。

- **サーバーも固定アドレスもない。** アプリの中に遮断できるアドレスは書かれておらず、ネットワークはどの単一ノードにも依存しません。
- **固定ポートがない。** 各端末は初回起動時にランダムなポートを選びます。Cleona の通信を識別できる既知のポート番号はありません。
- **乱数データのように。** 2台の端末間の接続確立は、乱数データと区別がつかないよう符号化されています。
- **多数の入口。** すべての招待、すべての隣人、同じ Wi-Fi 内のすべての端末が、ネットワークへ戻る経路になり得ます。

### 安全な鍵保管

対応プラットフォームでは、Cleona は暗号鍵をオペレーティングシステムの安全なキーリング（Android Keystore、iOS Keychain、macOS Keychain）に保存します。利用可能な場合、鍵に対してハードウェア支援の保護を提供します。

### データベースの暗号化

あなたのメッセージと会話は暗号化されたデータベースにあります――アイデンティティごとに1つ、それぞれ独自の鍵を持ちます。暗号化されるのはデータベース本体だけでなく、その中間ファイルもです。一時的であっても、暗号化されずにディスクに書き込まれるものはありません。設定、連絡先、メディアも同様に暗号化して保存されます。

鍵はあなたの24個の単語から導出され、あなたの端末にしか存在しません。あなたの端末を手に入れてデータを読み出しても、この鍵なしでは解読不能なデータしか見つかりません。

暗号化されないのは、あなたが自分でコンテンツを Cleona の外へ持ち出すところだけです。
- チャットのファイルを端末に保存するとき、
- スクリーンショットボタンで画像を画像フォルダに保存するとき、
- 何かを別のアプリに共有するとき、
- メディアのアーカイブを設定するとき（第13章）。アーカイブされたオリジナルは、Cleona なしでも開けるように、自宅のネットワークストレージ上に暗号化されずに置かれます、
- 予定を Android のシステムカレンダーにミラーリングするとき。そこでは、カレンダーへのアクセス権を持つ他のアプリがそれらを読めます。

このように外へ出たものは、メッセージと一緒に削除されず、メッセージと一緒に期限切れにもなりません。

### 画面上の保護

Android、Windows、macOS では、Cleona は他のアプリによる画面録画を許しません。画像が必要なときは、上のバーのスクリーンショットボタンを使ってください。それは画像をあなたの画像フォルダに保存します――暗号化されずに。転送が許可されていない会話では、スクリーンショットはありません。

## 15. ソフトウェアアップデート

### アップデートをどう受け取るか？

Cleona は複数の経路で更新できます。狙いは、個別の配布経路が止まったり遮断されたりしても、アップデートを受け取れるようにすることです。

1. **App Store / Play Store:** Cleona がそこに登場し、いずれかのストア経由でインストールした場合、いつも通りストア経由でアップデートを受け取ります。iPhone では、アップデートは TestFlight 経由で届きます。
2. **GitHub Releases:** プロジェクトの GitHub ページに、すべてのプラットフォーム向けの署名付きインストールパッケージがあります。
3. **ネットワーク経由のアップデート:** Cleona はアップデートをネットワーク経由で直接取得できます――ダウンロードサーバーなしで。新しいバージョンは誤り訂正付きの断片に分かれてネットワークに分散し、その一部はカバートラフィックにさえ同乗します。あなたの端末が十分な断片を集め、アップデートを組み立てます。転送されるのは通常、変更分だけです――アプリ全体の代わりに数 MB。これは Linux、Windows、Android に当てはまります。macOS では、新しいバージョンをウェブサイトまたは GitHub からダウンロードします。
4. **招待リンク:** 新しい利用者が Cleona をインストールしネットワークに接続するために必要なすべてを含む招待リンクを作れます。
5. **物理的な転送:** インターネットのない環境では、USB メモリやローカルネットワークで Cleona を他者に渡せます。

### アップデートの流れ

1. Cleona は新しいアップデートの断片をバックグラウンドで自動的に集め、組み立てます。
2. アップデートが**完全に**揃い、その**署名が検証**されて初めて、Cleona はあなたに提案します。つまり、中途半端な、あるいは未検証のアップデートが提案されることはありません。
3. 「インストール」をタップすると、追加の問い合わせなしにインストールが始まります。Android では、システムが追加でインストールダイアログを表示します。

古いバージョンは提案されません――アップデートは常に前進のみです。あるバージョンが古すぎてネットワークと協働できなくなると、Cleona はそれを明確に表示し、更新を促します。

### 署名検証

すべてのアップデートは二重に署名されています：古典的手法とポスト量子手法で。Cleona は両方の署名を自動的に検証します。これにより、アップデートがネットワーク経由で未知の端末から来た場合でも、公式開発者からのものだけが受け入れられることが保証されます。アップデートは開発から自動的に生じることはなく、開発者が手作業で署名した場合にのみ生じます。

## 16. よくある質問

### 「インターネットなしで Cleona を使えますか？」

Cleona はネットワーク接続を必要としますが、必ずしもインターネットとは限りません：同じ Wi-Fi では、Cleona の端末同士が自分たちで見つけ合い、インターネットアクセスなしでやり取りできます。相手と同時にオンラインである必要もありません：相手がオフラインなら、メッセージは3人の隣人のメールボックスで最大7日間、相手が取りに行くまで待機します。

### 「シードフレーズを失くしたら？」

あなたのアイデンティティを持つ端末がまだ1台動いていれば、何も失われていません――そこでそのまま書き続ければよいのです。アイデンティティを作成した端末では、24個の単語を大抵は再度読めます（第2章を参照）。ただし、これに頼ってはいけません。再インストールでこのコピーは消去され、Android では画面ロックの削除や変更でも失われます。単語も端末もない場合、戻る道はありません――連絡先も、開発者も、他の誰であっても。だからこそ、24個の単語を安全に保管することが重要です。

### 「誰かが私のメッセージを読めますか？」

いいえ。各メッセージはその1通のためだけの使い捨ての鍵で暗号化されます。あなたと相手だけがメッセージを復号できます。中央サーバーも、合鍵も、開発者へのアクセスもありません。転送経路上の端末がメッセージを中継しても、それは暗号化されたデータの塊とコードしか見ません。あなたの隣人は、パケットがあなたから来たことを知っていても、誰へ行くかを知りません。相手の隣人は、誰へ行くかを知っていても、誰から来たかを知りません。

### 「なぜ電話番号が不要なのですか？」

あなたのアイデンティティが純粋に暗号学的だからです。本名に紐づく電話番号やメールアドレスの代わりに、あなたの端末で生成された鍵ペアがあなたを識別します。連絡先は QR コード、NFC、またはあなたの招待のテキスト行で追加します――電話帳経由ではありません。これはプライバシーの向上を意味します。あなたのメッセンジャーアカウントが現実のアイデンティティに縛られないからです。

### 「Cleona で人を見つけるには？」

Cleona には意図的に、電話番号や名前での連絡先検索がありません――それはプライバシーの問題になるからです。代わりに、招待を直接交換します：QR コード、NFC、または別の経路でのテキスト行で。これは、電話帳を探すのではなく、名刺を交換するようなものです。

### 「Cleona は海外でも動きますか？」

はい。インターネット接続がある限り、Cleona は世界中どこでも動きます。中央サーバーも固定アドレスもないため、特定の国向けにサービスを簡単に遮断することはできません。Cleona が遮断をどう困難にするかは、「セキュリティ」の章の「検閲耐性」にあります。ただし、国境で未知の通信をすべてブロックする国は、Cleona も止めることができます。

### 「Cleona は無料ですか？」

はい。Cleona は無料で、広告なしで利用できます。中央サーバーがないため、運用にかかるサーバー費用も発生しません。設定の「Cleonaを応援」→「寄付」で、開発を任意で支援できます。

### 「メッセージにチェックが1つしかありません――どういう意味ですか？」

メッセージは配信中ですが、相手がまだ受信を確認していません――たいてい、相手がいまオフラインだからです。これはエラーではありません：メッセージはメールボックスで最大7日間待機します。相手が取りに行くと、チェック2つが見えます。時計は、まだどの経路もメッセージを運んでいないことを意味します――経路ができ次第、自動的に送信されます。警告記号は、14日間どの経路も見つけられなかったことを意味し、再送できます。

### 「なぜ私のiPhoneではメッセージが遅れて届くのですか？」

iOSはアプリをバックグラウンドで常時動かせません。Cleonaは時々短時間だけ起こされます。いつ起こすかはiOSが決めます。そのとき、すべてを受け取りに行きます。アプリを開くとすぐ、Cleonaはあなたのために保管されていたものを受け取りに行きます。

### 「WhatsApp から Cleona に乗り換えられますか？」

はい。ただし、WhatsApp のチャットを転送することはできません。Cleona と WhatsApp は根本的に異なるシステムです。連絡先を Cleona に1人ずつ追加する必要があります。最も簡単なのは、あなたの招待のテキスト行を連絡先に送ることです。そうやって届いた各リクエストは、あなたが「リクエスト」で自分で承認します。

### 「複数の端末で Cleona を同時に使えますか？」

まだできません。同じアイデンティティ用の2台目の端末は、今後のバージョンで使えるようになります（第11章）。複数の端末では、今日は異なるアイデンティティを使えます。

### 「App Store が遮断されていたら、どうアップデートを受け取りますか？」

Cleona は App Store、ウェブサイト、ダウンロードサーバーに依存せず、ネットワーク経由で直接アップデートを取得できます。ネットワーク内の別の端末が最新版を持っていれば、あなたの端末はそこからアップデートを読み込めます。真正性は開発者のデジタル署名で検証されます。あるいは、連絡先が招待リンクや USB メモリでアプリを渡すこともできます。詳しくは「ソフトウェアアップデート」の章を参照してください。

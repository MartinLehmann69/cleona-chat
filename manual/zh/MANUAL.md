## 1. 什么是 Cleona Chat？

### 你的 messenger，你的数据

Cleona Chat 是一款完全无需中央服务器即可运行的 messenger。你的消息从你的设备直接传到对方的设备——不经过任何公司总部，不经过云，不经过数据中心。途中若有其他设备帮忙，它也只是转发加密的数据包。没有任何企业能够读取、存储或转发你的消息，因为根本没有企业夹在中间。

### 无账号，无电话号码

使用 Cleona，你既不需要电话号码也不需要电子邮箱来注册。你的身份由一对密钥组成，这对密钥在你首次启动时自动在你的设备上生成。这意味着：没有人能通过你的电话号码或邮箱地址找到你，除非你自己把联系方式告诉别人。

### 面向未来的加密

Cleona 使用所谓的后量子加密。也就是说：即便是未来的量子计算机也无法破解你的消息。你不必理解其中的细节——重要的是，你的通信按照当前的技术水平得到了尽可能好的保护。

### 没有服务器是怎么做到的？

Cleona 的网络只由其用户的设备组成。每台设备都是一个节点，没有哪个节点比另一个更重要，每个节点只认识自己的邻居。四件事让这个网络与众不同：

- **没有固定点。** 应用里没有服务器地址，网络也不依赖于任何单个节点。没有什么东西可以被关闭来让 Cleona 停摆。
- **即时。** 你的消息在你发送的那一刻就出发了。它不等任何节拍，也不等任何别的东西。
- **顺便掩护。** 你的设备持续发送小小的掩护数据包，这样从外面就看不出你什么时候真正在写消息。没有任何消息依赖于它——掩护只是在旁边运行。
- **用代码而不是名字。** 转发消息的人只看到一个每天都会变化的代码。正常情况下，他们当中没有任何人同时认识发送者和接收者；例外情况见第 14 章。

**三条路径，同时进行。** 当你发送一条消息时，Cleona 不是一条路径接一条路径地试，而是把所有合适的路径同时启动。一旦对方确认收到，其余路径就会被取消。

1. **在同一个网络中：** 如果你们在同一个 Wi-Fi 中，消息会直接传过去。
2. **经由固定邻居：** 在互联网中，你的设备把消息交给它的固定邻居。后者把它转发给你对方的固定邻居（最多三个同时进行），其中之一完成投递。
3. **信箱：** 如果你的对方离线，Cleona 会把消息加密存放在三个邻居那里。它在那里最多保留 7 天。当你的对方重新上线，就会把它取走。

**你怎么进入网络？** 应用里没有服务器地址。你的入口来自你的第一个联系人：他的邀请包含一些地址，你的设备通过它们找到自己最初的邻居。在同一个 Wi-Fi 中，Cleona 设备也会自行互相发现。从那时起，你的设备每认识一个邻居，就通过它认识更多邻居。

### 平台

Cleona 可用于 Android、iOS、macOS、Linux 和 Windows。在电脑和 Android 上，消息和通话会在几秒内到达。在 iPhone 上，这一点仅在应用打开时成立。应用未打开时，iOS 只会偶尔将它短暂唤醒；何时唤醒由 iOS 决定。随后 Cleona 会取回为你保存的全部内容，并在应用图标上显示带数字的通知。通话无法到达应用未打开的 iPhone。这是 Apple 的规定，不是 Cleona 的缺陷。

## 2. 入门

### 安装应用

**Android：**
1. 从 Cleona 网站或 GitHub Releases 下载 APK 文件。
2. 在手机上打开该文件。如有必要，允许从未知来源安装（Android 会自动询问你）。
3. 点击"安装"并等待安装完成。

**iOS：**
1. 在 iPhone 上打开 TestFlight 邀请链接。
2. 点击"安装"。TestFlight 是 Apple 用来分发 beta 应用的官方方式。
3. 安装完成后，你会在主屏幕上找到 Cleona。

**macOS：**
1. 从 Cleona 网站或 GitHub Releases 下载 DMG 文件。
2. 打开 DMG 并把 Cleona 拖到你的"应用程序"文件夹。
3. 首次启动时，macOS 可能会询问你是否要打开来自一位已识别开发者的应用——予以确认。

**Linux（Ubuntu/Debian）：**
1. 从 Cleona 网站或 GitHub Releases 下载 .deb 文件。
2. 双击安装，或在终端中执行：`sudo dpkg -i cleona-chat-beta_VERSION_amd64.deb`
3. 从应用菜单启动 Cleona，或在终端中执行 `cleona-chat-beta`。

**Linux（Fedora/openSUSE）：**
1. 从 Cleona 网站或 GitHub Releases 下载 .rpm 文件。
2. 执行安装：`sudo dnf install cleona-chat-beta-VERSION-1.x86_64.rpm`
3. 从应用菜单启动 Cleona，或在终端中执行 `cleona-chat-beta`。

**Linux（所有发行版 -- AppImage）：**
1. 从 Cleona 网站或 GitHub Releases 下载 .AppImage 文件。
2. 将该文件设为可执行：右键、属性、可执行，或在终端中执行：`chmod +x cleona-chat-beta-VERSION-x86_64.AppImage`
3. 双击启动，或在终端中执行：`./cleona-chat-beta-VERSION-x86_64.AppImage`

这些包名适用于 beta 版，它是目前唯一公开发布的版本；它名为 `cleona-chat-beta`。

**Windows：**
1. 从 Cleona 网站或 GitHub Releases 下载安装程序。
2. 运行安装文件并按照提示操作。
3. 从开始菜单或桌面快捷方式启动 Cleona。

### 创建身份

首次启动时，Cleona 会自动为你创建一个新身份。你可以给自己取一个显示名——这是你的联系人看到的名字。这个名字随时可以更改。

### 抄写助记词——最重要的事

创建身份后，Cleona 会向你显示 24 个单词。这就是你的**助记词**——你个人的恢复密钥。

**把这 24 个单词抄在纸上并妥善保管。**

为什么这如此重要？

- 如果你的手机坏了、丢了或被偷了，你可以用这 24 个单词在一台新设备上恢复你的整个身份。
- 没有助记词就没有回头路。没有"忘记密码"按钮，也没有能把你账户还给你的客服——因为服务器上根本就没有账户。你的联系人也无法恢复你的身份，无论有多少个。装有同一身份的第二台设备将在后续版本中提供（见第 11 章）。
- 绝不要把助记词透露给他人。谁认识这些单词，谁就能冒充你。

你之后也可以在设置中的"备份"→"显示恢复短语"项下找到这 24 个单词，以备你想重新查看。在 Android 上，你需要用你的屏幕锁定方式予以确认。

### 添加第一个联系人

要和某人聊天，你必须先把他添加为联系人。这有多种方式——下一节会逐一讲解。

## 3. 联系人

### 你的邀请

在 Cleona 中，联系人只能通过邀请产生。你的邀请从首次启动起就存在——即使没有网络，甚至在你的设备尚未找到任何邻居之前。你可以在身份详情页找到它（点顶部栏中你自己的名字）。

邀请有两种形式，内容完全相同：

- 以**二维码**形式，当你的对方就站在你身边时使用；以及
- 以**文本行**形式，你可以通过电子邮件、短信或别的 messenger 发送。

邀请不包含电话号码，也不包含来自某个目录的名字。它包含你的公钥以及对方用来联系你和你的邻居的地址。因此，对一个刚安装 Cleona 的人来说，你的邀请也是他进入网络的入口。

### 扫描二维码（推荐）

如果你们当面见面：

1. 你向对方展示你邀请的二维码。
2. 对方点击加号按钮，选择"扫描二维码"，把摄像头对准你的屏幕。用电脑的摄像头也可以。
3. 请求发给你并**自动接受**——因为这个代码是你刚刚亲自展示的。

一个二维码只有效一次：第一个有效请求会被接受，之后邀请即被消耗。二维码是最安全的方式，因为你们在此时确切知道在和谁交换联系人。

### NFC（手机互碰）

如果两台设备都支持 NFC：

1. 双方都打开添加联系人功能。
2. 把你们的手机背靠背贴在一起。
3. 邀请被传输并自动接受。

NFC 和二维码一样具有很高的安全性，因为只有当你们物理上站在一起时交换才会起作用。

### 发送文本行

如果你们无法见面：

1. 打开你的邀请并复制文本行。
2. 把它发给要添加你的人——通过邮件、短信或别的 messenger。
3. 对方在 Cleona 的添加联系人对话框中粘贴该行。
4. 请求出现在你这里的**"请求"**下。这里**不会**自动接受：由你自己决定，因为你无法知道这行文字在途中还被谁读过。

### 接受联系人请求

收到的请求还不会产生联系人。它会向你提出一个问题，并出现在**"请求"**标签下。在那里你能看到名字和验证级别，并可以选择：

- **接受**——此时此人才成为你的联系人。
- **拒绝**——请求被丢弃。
- **屏蔽**——此人不能再向你发送更多请求。

### 从不作为固定邻居使用

在某个联系人的菜单中，你会找到**"从不作为固定邻居使用"**开关（默认：关）。开启后，该联系人不为你转发消息，因此也不会知道你何时发送或接收消息。这是为你的威胁来自你自身环境的情况而设计的。

对于陌生人（既不是联系人，也不是共同群组的成员），Cleona 除了这样的请求之外什么也不放行——没有消息、没有通话、没有文件。而且即便是请求，也只有当发送者事先解开了一道小小的计算题时才会送达。这让大规模垃圾发送变得昂贵。

### 验证级别

Cleona 会告诉你某位联系人的身份得到了多可靠的确认：

| 级别 | 含义 |
|-------|-----------|
| 未验证 | 你们已连接，但没有任何东西确认背后真的是正确的那个人。 |
| 已看到 | 密钥交换成功，你们可以加密通信。 |
| 已验证 | 你们当面见过面，并通过摄像头扫描或 NFC 连接。 |
| 受信任 | 你已明确将此联系人标记为值得信任。 |

"已验证"只适用于当面交换。通过聊天或邮件得到的邀请永远达不到这一级别——即使它包含相同的数据。

如果某位联系人的密钥在没有通知的情况下发生了变化，Cleona 会将他重置为"未验证"。这能保护你，防止有人在你不知情的情况下冒充你的联系人。

## 4. 消息

### 发送和接收文本

只需在底部的输入框里输入你的消息，然后按回车或发送按钮。你的消息会在离开你的设备之前被自动加密。

收到的消息会出现在聊天记录中。

### 消息上的标记代表什么

| 标记 | 含义 |
|---------|-----------|
| 时钟 | 消息已创建，但还没有任何路径承载过它。 |
| 一个勾 | 消息在途中。当它在信箱中等待你的对方时也是如此。 |
| 两个勾 | 已送达：你对方的设备已确认收到。 |
| 警告标记 | 连续 14 天没有任何路径承载这条消息。点击它可重新发送。 |

**离线不是错误。** 如果你的对方不可达，消息会停在一个勾，直到被取走——它不会丢失。如果你自己的设备没有连接，消息会停留在时钟状态，并在一旦重新有路径时自动发出。警告标记只有在消息连续 14 天未找到任何路径时才会出现；这时你可以重新发送它。

这对应用未打开的 iPhone 同样适用：消息会在信箱中等待，直到 iOS 短暂唤醒应用，或直到对方打开它。这可能比在其他设备上耗时更长。

只有当接收者本人确认收到时才会出现两个勾。这份回执是加密且签名的——途中没有任何人能伪造它来向你假装已送达。

### 发送图片、视频和文件

你有多种方式：

- 输入框中的**回形针图标**：点击它，可从你的相册或文件系统中选择一个文件、图片或视频。
- **拖放**（桌面版）：把一个文件直接拖进聊天窗口。
- **从剪贴板粘贴**（桌面版）：复制一张图片并在聊天中粘贴。

小文件（小于 256 KB）直接随消息一起传输。较大的文件会被拆分成片段并加上纠错码，这样丢失个别片段也不影响。如果你们双方都在线，它们会经由一个邻居流式传输；否则它们会被存放在持续可达的设备上，直到你的对方来取。

从 256 KB 起，Cleona 会在每个文件发送前逐一询问你：大文件无法走你消息的路径。文件内容保持加密，你的对方也不会得知你的互联网地址。但这次传输从外面可以被看成一个事件，而转发或保存它的陌生设备会看到谁在上传、谁在取走。你的同意只对这一个文件有效。

### 语音消息

1. 长按输入框中的麦克风按钮。
2. 说出你的消息。
3. 松开按钮以发送消息。

如果你的设备上启用了语音识别（见设置），你的语音消息会自动被转录成文字。你的对方随后会同时看到录音和转录后的文字。

### 回复消息（引用）

要回复某条特定消息：

1. 打开该消息旁边的三点菜单。
2. 选择"回复"。
3. 输入框上方会出现一个带有所引用消息的横幅。
4. 写下你的回复并发送。

被引用的消息会显示在你的回复中，使对应关系一目了然。

### 编辑和删除消息

- **编辑：** 打开该消息的三点菜单，然后选择"编辑"。修改文字并重新发送。你的对方会看到该消息已被编辑。在发送后的 15 分钟内可以编辑。
- **删除：** 打开该消息的三点菜单，然后选择"删除"。该消息会从你和你对方的设备上移除。你可以随时删除自己的消息——删除没有时间窗口限制。

### Emoji 反应

与其写一条回复，你可以用一个 emoji 对一条消息作出反应：

1. 打开三点菜单或长按该消息。
2. 从快速选择中选一个 emoji，或打开 emoji 选择器以获得完整选择。
3. 你的反应会出现在该消息下方。

### 复制文字

通过某条消息的三点菜单，你可以把消息文字复制到剪贴板。

### 搜索消息

在聊天窗口的顶部边缘你会找到搜索功能。输入一个搜索词，Cleona 会向你显示当前聊天中的所有匹配项。用箭头键你可以在匹配项之间来回跳转。

在主页上还有一个跨标签的搜索过滤器，你可以用它按一个词搜索所有对话。

### 链接预览

当你发送一个链接时，Cleona 会自动生成预览（标题、描述、预览图）。此预览由你的设备创建并随消息一起发送——你的对方不必为此连接到被链接的网站。

点击一个收到的链接会发生什么，你在设置中的"链接打开方式"项下设置："普通"、"优先使用无痕窗口"（在设备无法打开无痕窗口的地方，链接会正常打开）或"每次询问"。

## 5. 群组

### 创建群组

1. 切换到"群组"标签。
2. 点击加号按钮。
3. 给群组取个名字。
4. 选择你想邀请的联系人。
5. 点击"创建"。

被邀请的联系人会收到通知并可以加入群组。

### 群组消息如何受到保护

在最多 16 名成员的群组中，Cleona 会把每条消息单独发给每位成员——每条都只为该成员加密，就像你给每个人单独写了一条消息一样。群组消息上的勾显示进展最慢的那位成员的状态。

群组超过 16 名成员时，会使用一个共享密钥。它每天都会变化，并在有成员退出或被移除时重新生成；新成员只能从加入之时起阅读。此时勾不再显示每位成员的进度，而是表明消息已存放在网络中。当群组人数降回 12 名或更少，会重新回到单独发送。

### 群组和频道中的图片

在群组或频道的设置中，你可以通过"始终加载图片"来设定图片是立即加载，还是等你点击某张图片时才加载。

### 邀请成员

即使在创建之后，你仍可以邀请更多联系人：

1. 打开群组信息（群组列表中的三点菜单，或群组聊天中的顶部栏）。
2. 点击"邀请"。
3. 选择你想添加的联系人。

### 角色

每个群组有三种角色：

- **所有者（Owner）：** 拥有全部控制权。可以添加和移除成员、任命管理员以及管理群组。所有者也可以把自己的身份转让给另一名成员。
- **管理员：** 可以移除成员并协助管理。
- **成员：** 可以阅读和发送消息。

### 离开群组

1. 打开群组列表中的三点菜单。
2. 选择"离开"。
3. 确认你的决定。

当你离开一个群组时，你此前的消息对其余成员仍然可见。

## 6. 公开频道

### 什么是频道？

频道是 Cleona 网络内的公开讨论论坛。与群组不同，这里任何人都可以阅读，无需被邀请。只有所有者和管理员可以发布内容——订阅者只读。

### 查找并加入频道

1. 切换到"频道"标签。
2. 打开"搜索"选项卡。
3. 按名字或主题搜索可用频道。
4. 点击一个频道，然后点击"订阅"。

频道可以按语言筛选。有些频道被标记为"非青少年适宜"——只有当你在个人资料中确认自己已满 18 岁时，它们才可见。

### 创建自己的频道

1. 切换到"频道"标签。
2. 点击加号按钮。
3. 输入频道名（必须在整个网络中唯一）。
4. 选择语言以及频道是公开还是私密。
5. 可选：添加描述和图片。
6. 点击"创建"。

对于公开频道，你可以设定内容是否被归类为"非青少年适宜"。

### 举报内容

如果你在某个公开频道中注意到不当内容，可以举报它。Cleona 使用去中心化的审核系统：举报由网络中随机选出的成员来评判（一种"陪审团"）。若确认违规，频道会收到一次警告。在多次违规后，它会在搜索索引中被降级或被封禁。

### 系统频道

Cleona 内置两个系统频道：

- **Bug 日志：** 当 Cleona 识别到一个错误时，它会询问你是否要发送一份错误报告；发送前你会确切看到将要公布的内容。这些报告会进入 Bug 日志频道，社区可以在那里查看它们。报告不包含名字，也不包含你对话的内容，而只有一个化名。在 beta 版中，它还会附带你的标识（User-ID），以便开发者进行追问。你也可以手动发送一份日志报告（带预览对话框和明确的同意）。
- **功能请求：** 在这里用户可以提交功能愿望，并对已有建议投票。建议按票数排序。

每台电脑为每个系统频道保留最多 25 MB，每部手机最多 5 MB；满了之后最旧的先被清出——被清出的永远不会是你已经看过的内容。

## 7. 通话

### 发起语音通话

1. 打开与你想呼叫的联系人的聊天。
2. 点击顶部栏中的电话图标。
3. 等待对方接听。

通话期间你会看到一条时间线、通话时长，并可使用静音和扬声器。

要挂断，请点击红色的挂断按钮。

如果你看到"无法接通"，说明对方的设备目前无法访问，例如应用未打开的 iPhone。请改为发送消息。

### 发起视频通话

1. 打开与该联系人的聊天。
2. 点击顶部栏中的摄像头图标。
3. 你的视频画面会出现在一个小窗口中，你对方的画面在主区域。

你可以在通话期间在前置和后置摄像头之间切换。

### 来电

当有人呼叫你时，会出现一个带呼叫者名字的通知窗口。你可以：

- **接听**——通话开始。
- **拒绝**——呼叫者会收到通知。

如果你正在通话中，新的来电不会响铃；取而代之，你会收到一条"未接来电"消息。对于你没有接听的群组通话也是如此——这条消息会显示在群组聊天中。

如果有人呼叫你当前没有显示的某个身份，它照样会响铃；通话画面会指明被呼叫的是你的哪个身份。

在 iPhone 上，只有应用打开时才会响铃。在应用未打开时呼叫你的人，会在 10 秒后看到"无法接通"。你一打开应用，就会看到一条未接来电消息。

### 群组通话

你也可以进行多人同时参与的群组通话。通话通过一个智能的中继树来组织，这样并非每位参与者都要与其他每位直接相连。所有通话全程加密。

每个群组成员都可以发起群组通话。两位互不是联系人的参与者永远看不到对方的互联网地址：他们的声音和画面经由一位与他们双方都是联系人的参与者传输。如果没有这样的人，这两位就不会相连，界面上会显示"通话中没有共同联系人"。如果一条中继已满负荷，这一对参与者的声音会保留，视频则被取消。

### 通话的加密

所有通话都用一次性密钥加密，这些密钥仅在通话期间存在。挂断后这些密钥会立即被删除。没有人能在事后解密一段过去的通话。

坦白地说：通话会尽可能直接在设备之间进行，因为即使很小的延迟也会妨碍说话。与消息不同，你的互联网服务提供商因此在通话时能看到你连接的是哪个互联网地址。你们说了什么，他看不到。

通话时，你的联系人也会看到你的互联网地址。如果你不想让某位联系人看到这一点，可以在他的菜单中关闭"允许通话"（默认：开）。如果之后才关闭，他已经看过的地址仍为他所知。

## 8. 日历

Cleona 包含一个内置日历，它加密且完全去中心化地运行——无需云服务。

### 视图

日历提供五种视图：日、周、月、年，以及一个任务视图。通过日历屏幕顶部的标签在它们之间切换。

### 创建日程

点击一个时间段或使用添加按钮来创建一个新日程。你可以输入标题、日期、时间、地点和备注。日程会加密存储在你的设备上。

### 重复日程

日程可以每日、每周、每月或每年重复。你可以调整模式（例如每隔一个周二、每月第一天），并设定结束日期或重复次数。

### 邀请联系人

在创建或编辑日程时，你可以邀请你的 Cleona 联系人。他们会收到一份加密的日历邀请，并可以回复接受、拒绝或待定。对日程的更改会自动发送给所有被邀请者。

### 空闲/忙碌显示

你可以与联系人分享你的空闲情况，而不必透露日程细节。有三个隐私级别：完整细节、只显示时间段、或隐藏。你可以设置一个默认值，并针对每个联系人单独覆盖。

### 提醒

日程可以带提醒，在日程开始前触发一条系统通知。如有需要，你可以让提醒稍后再响。

### 外部日历同步

Cleona 可以与外部日历服务同步：

- **CalDAV** —— 连接任何兼容 CalDAV 的服务器（Nextcloud、Radicale 等）。
- **Google 日历** —— 通过 Google Calendar API 同步，采用安全的 OAuth2 认证。
- **本地 CalDAV 服务器** —— Cleona 可以在你的设备上启动一个本地 CalDAV 服务器，这样桌面日历应用（Thunderbird、Outlook、Apple 日历、Evolution）就能与你的 Cleona 日历同步。
- **Android 系统日历** —— Cleona 中的日程可以传输到你 Android 设备上内置的日历应用。
- **ICS 文件** —— 以标准 iCalendar 格式导入和导出日程。

### PDF 导出

你可以把任何日历视图（日、周、月、年）打印或导出为 PDF 文档。

## 9. 投票

你可以在任何聊天或群组中创建投票，以征集意见或安排日程。

### 投票类型

Cleona 支持五种投票：

- **单选** —— 参与者选择一个选项。
- **多选** —— 参与者可以选择多个选项。
- **时间投票** —— 找一个对所有人都合适的时间。每位参与者把时间标记为有空、待定或没空。
- **量表** —— 在一个数字量表上评价某物（例如 1 到 5）。

### 创建投票

打开一个聊天并点击投票图标（或使用附件菜单）。选择投票类型，写下你的问题和选项，然后发送投票。它会作为一条消息出现在聊天中。

### 投票

点击一个投票来投出你的票。你可以随时更改或撤回你的票。

### 匿名投票

投票可以配置为匿名投票。启用后，投票在密码学上是匿名的——没有人，连投票创建者也无法看到谁投了什么。票数仍然可见。

### 时间投票转日历

当一次时间投票结束时，胜出的时间可以一键直接转换为一个日历条目。

## 10. 多个身份

### 为什么要有多个身份？

设想你想把职业生活和私人生活分开——就像用两个不同的电话号码，但不必用两部手机。在 Cleona 中，你可以在一台设备上使用多个身份。每个身份有自己的名字、自己的头像、自己的联系人和自己的对话。

### 创建新身份

1. 在顶部栏中，你当前的身份以标签形式显示。
2. 点击你身份标签右侧的加号（+）。
3. 为新身份输入一个名字。
4. 完成——新身份立即生效。

### 在身份之间切换

只需点击顶部栏中的身份标签。切换是即时的——没有等待时间，无需重新加载。

### 全部同时运行

重要的一点：你所有的身份都同时处于活动状态。即使你当前显示为"职业"，你的"私人"身份也继续接收消息。无论你当前选择了哪个身份，你都不会错过任何东西。

### 身份详情页

当你点击你当前活动身份的标签时，会打开详情页。在这里你可以：

- 显示用于联系人的二维码。
- 更改或移除你的头像。
- 添加一段个人资料描述。
- 更改你的显示名。
- 为此身份选择一个主题（皮肤）。
- 在不再需要时删除该身份。

### 删除身份

当你删除一个身份时，你的联系人会收到通知。该身份及其所有相关数据会从你的设备上移除。此过程不可逆转。

## 11. 多台设备

### 一个身份，一台设备——暂时

如今一个身份运行在一台设备上。用于同一身份的第二台设备将在后续版本中提供；因此在设置中的"设备"→"管理设备"下，"配对更多设备"目前仍显示为"暂不可用"。

等它到来时规则是：所有设备一律平等，没有主设备。你用你的 24 个单词设置一台新设备，并由你现有设备中的一台予以同意。最多 5 台设备。

如果你如今在一台新设备上输入你的 24 个单词，你就是在搬家：身份会被恢复到新设备上，而你此前的设备随后会将身份从自己这里移除（见第 12 章）。

如今你可以在多台设备上使用不同的身份（第 10 章）。

### 为身份轮换密钥

如果你怀疑有人拿到了你的密钥，你可以在"管理设备"→"轮换密钥"下生成新密钥。你的联系人会收到通知，你处于开放状态的邀请会被撤销。重要：此后这 24 个单词本身只能恢复出旧密钥。因此请在这之后立即创建一个新的恢复包；此后你只能连同这个包一起恢复。

## 12. 恢复

### 使用助记词

当你丢失设备或设置新设备时：

1. 在新设备上安装 Cleona。
2. 在启动时选择"恢复"。
3. 输入你的 24 个单词。
4. Cleona 会据此重新生成你所有的身份——使用与之前相同的密钥。对你的联系人来说，你还是同一个人。

### 会回来什么——以及不会回来什么

你的身份就在那 24 个单词里，你的联系人和聊天记录则不然。通过**恢复包**回来的是你的网络接入：你的设备会在网络中存放一个小小的加密包。只有你的 24 个单词能找到并打开它。里面写着你的新设备重新联系上你的联系人所需的内容，以及等待期间网络中为你存放的内容。为此不需要任何联系人在线。

恢复不会带回此前的聊天记录。

恢复包的有效期为 7 天，只要你的设备在运行就会续期；在设置中你可以看到它的有效期到何时。如果你的设备没有任何一台运行超过 7 天，它就过期了。那时这 24 个单词仍然能恢复你的身份，但你的联系人必须重新邀请；等待期间网络中为你存放的内容则丢失了。

### 恢复就是搬家

如果你此前的设备后来发现身份已在别处恢复，它会将身份连同其聊天记录从自己这里移除。因此：拥有你 24 个单词的人，可以通过这种方式把你的身份从你的设备上取走。在所有联系人重新回来之前，应用会提醒你；你用"完成并更新密钥"自行结束恢复过程。

### 没有人能恢复的东西

这很重要，因此我们明确说出来：

- **除了你，没有人能恢复你的身份。** 不是开发者，不是客服，也不是你的联系人——无论有多少个。没有万能密钥，也没有任何一部分你的密钥被托管在别处。
- **如果你丢了那 24 个单词并且不再有任何设备，你的身份就丢失了。** 那时唯一的办法是创建一个新身份并重新邀请你的联系人。

最好的保护：把 24 个单词写在纸上并妥善保管。

## 13. 设置

你可以通过右上角的齿轮图标进入设置。

### 通知和铃声

- 从六种不同的来电铃声中选择。
- 设置一个消息提示音。
- 在 Android 设备上你还可以额外启用或禁用振动。
- **"全部静音"**让这台设备上不再有任何消息响铃、振动或提示——对所有身份都生效。通话仍会响铃。
- **"免打扰时段"**你为每个身份分别设置起止时间。在这段时间内，该身份的任何消息都不响铃、不振动、不提示；消息仍然会送达。
- **"无内容通知"**（默认：关）只显示一条消息、邀请或提醒已到达——不带发送者、名字和内容。通话仍显示名字。
- 对于启动后一次性到达的内容，Cleona 会用一条汇总通知告知（"5 条新消息，分布在 2 个对话中"）；之后的一切则逐条提示。点击一条消息通知即可打开对应对话，即使它属于另一个身份。

### 主题（皮肤）

Cleona 提供十种不同的主题：Teal、Ocean、Sunset、Forest、Amethyst、Fire、Storm、Slate、Gold 和 Contrast。Contrast 主题满足最高的无障碍级别（WCAG AAA），在视力受限时特别易读。

每个身份可以有自己的主题。你在身份详情页（点击当前活动的身份标签）更改主题。

此外你可以在设置中的"外观"项下在浅色、深色和系统主题之间切换。

### 更改语言

Cleona 提供 34 种语言，其中包括从右向左书写的语言（例如阿拉伯语、希伯来语）。在设置中的"语言"项下更改语言。

### 媒体归档

如果你家里有一台网络存储（NAS）或一个共享文件夹，Cleona 可以把你的媒体自动外移到那里。支持 SMB、SFTP、FTPS 和 WebDAV。

分级存储是这样工作的：
- 前 30 天：一切都留在你的设备上。
- 30 天后：一张缩略图留在设备上，原件被归档。
- 90 天后：只有一张小缩略图留在设备上。
- 一年后：只剩一个占位符，原件安全地存放在归档中。

你可以随时点击一个已归档的媒体把它取回——前提是你已连接到你的家庭网络。特别重要的媒体可以置顶，这样它们永远不会被外移。

在"存储预算"下，你设定有多少 MB 的媒体留在设备上（默认：手机 100 MB，电脑 2 GB）。存满后，最旧的未置顶媒体会最先被归档。只有当原件已安全存放在归档中时才会被删除——文本消息始终保留。

### 语音消息转录

启用后，你的语音消息会在你的设备上本地转换为文字（使用开源模型 Whisper）。转录后的文字会与录音一起发送给对方。转录完全在你的设备上进行——没有任何数据发送到外部服务。

下载哪个模型（tiny、base、small），你为设备一次性设置；语言（自动或固定）则按身份分别设置。

### 自动下载

你可以设定从多大起媒体应被自动下载。例如你可以让图片自动加载，但对大视频手动决定。

### 设备

在"设备"→"管理设备"下，你可以看到这台设备。配对更多设备的功能将在后续版本中提供（第 11 章）。

### 网络

Cleona 不需要任何网络设置就能工作。有三个网络开关：

- **路由器端口转发**（默认：开）。Cleona 会请求你自己的路由器为 Cleona 开一扇门。如果成功，你的设备对其他人就更好达，并能帮助网络。Cleona 在此过程中只与你的路由器通信，不与互联网通信。
- **公开地址记录**（默认：开）。当你的设备邻居还太少时，它会在一个公开目录（Nostr）中查找更多入口点；而当它自身可达性很好时，会把自己登记进去。该记录包含一个地址，不含名字，也不含联系人。如果你关闭它，你的设备就只能通过邀请、本地网络和它已经认识的邻居来找邻居。
- **在 Wi-Fi 中减少掩护数据包**（默认：关）。在 Wi-Fi 或有线网络中你可以关闭空的掩护数据包。但那样在那里就又能看出你何时在写消息了。在移动数据中此开关不存在——在那里 Cleona 反正每分钟只发送一个掩护数据包。

掩护流量作为整体是无法关闭的。这是有意为之：只有当它一直在运行时，你设备的活动才不会透露你此刻是否在写消息。

三个开关的上方是**数据节省模式**：在移动数据中，Cleona 会向你建议开启它，但从不自行开启。它节省数据，代价是你的设备从外面更容易被识别。

在它们下方，你可以设置**"他人媒体缓存"**：你的设备最多为 7 天保存他人媒体的加密片段，以便它们送达各自的接收者（默认：手机 100 MB，电脑 1 GB）。改小容量会立即释放空间——最旧的片段先释放。

## 14. 安全

### 后量子加密是什么意思？

当今的加密基于对普通计算机来说极难求解的数学问题。量子计算机将来可能快速求解其中一些问题。后量子加密使用额外的方法，这些方法连量子计算机也能抵挡。

Cleona 结合了两套方案：经典加密用于可靠性，后量子方法用于面向未来。这样你就同时受到对当今和未来威胁的保护。

每一条单独的消息都会生成自己的密钥。即使攻击者破解了某条消息的密钥，他也无法借此读取任何其他消息。

### 为什么没有服务器更安全

在传统的 messenger 中，你的消息会经过提供商的服务器。即使它们在那里是加密的：提供商也能访问元数据（谁在何时与谁通信、多频繁、从哪里），并可能必须依司法命令交出这些数据。

在 Cleona 中没有这样一个中心点。没有所有元数据汇聚之处，也没有可以查阅你是谁或你认识谁的目录。

### 谁能看到你在和某人聊天？

加密保护的是你写**什么**。同样重要的是，没有任何单个观察者能知道你在**和谁**、**何时**聊天。为此 Cleona 这样做：

- **在互联网中从不直连。** 如果你的设备把消息直接发到你对方的互联网地址，你的提供商就能看到你在和谁聊天。因此在互联网中消息总是经由你们的固定邻居传输：你的和你的对方的。
- **你信任的邻居。** 你的固定邻居在可能的情况下是你自己联系人的设备——最多三个当前从外面可达的。如果其中一台掉线，另一位联系人顶上。联系人不会为了服务器而被收买；网络中任意的节点却可能。如果你还没有任何可达的联系人，Cleona 会取用另一个邻居。你的邀请从不提及你的任何联系人，这样没有人能通过他们得知你某个朋友的地址。
- **用代码而不是名字。** 邻居看到的不是名字和标识，而只是一个代码。它只对你们俩有效，单方向，只对一天——第二天就是另一个了。你的邻居知道数据包从哪里来，但不知道它最终去哪里。你对方的邻居知道它去哪里，但不知道它从哪里来。正常情况下，途中没有任何人同时看到两端。
- **掩护流量。** 你的设备以不规则的间隔持续向其邻居发送掩护数据包。它们与真实数据包一样大，走同一个端口，从外面无法与真实数据包区分。此刻是否真有人在写消息，还是只有设备在运行，因此无法分辨。你的消息从不等待掩护流量——它们立即出发，掩护只是在旁边运行。

**掩护流量的代价：** 在 Wi-Fi 中约为每天 13 MB。在移动数据中 Cleona 每分钟只发送一个掩护数据包，大约每天 1.7 MB。在移动数据中限速的原因不是数据量，而是电池：每个数据包都会唤醒无线调制解器。

**Cleona 无法隐藏的东西**——坦白地说：

- 没有**单个**观察者能看到谁在和谁写——你的提供商和途中的节点都不能。但谁若**同时监视两端**，例如一个国家监视你的接入点和你对方的接入点，或在两端各设下邻居，就能随着时间进行关联：数据包从你这里出去，紧接着数据包进入你对方那里。重复得足够多，就得出一条联系。
- 掩护流量使这种关联更难，但无法阻止。它隐藏单条消息，而不是总量：谁发送得非常多，就会提高自己设备的总流量。
- 一个作为你固定邻居的联系人会知道你**何时**以及**多少**地发送和接收——不知道和谁，也不知道什么。如果威胁来自你自己的环境，你可以让任何联系人免于此（见第 3 章，"从不作为固定邻居使用"）。
- 如果两位新用户只有同一个邻居，他们的消息就走经过这一个节点，而它能看到两端。一旦他们中任何一方有了更多邻居，这就结束了。
- 你的邀请包含你的互联网地址。谁拥有这行文本，就能看到你在哪里上线——只把它给你信任能做到这一点的人。
- 一个转发的邻居看到的是两个代码在交换数据包——不知道背后是谁，也不知道里面是什么。
- 通话进行中的一个信号，如果第一个邻居恰好没有应答，可能经由一个能看到两端的节点传输；它会得知你们正在一起通话。
- 你同意发送的大文件，转发或保存它的计算机会看到它的两端（见第 4 章）。
- 对于通话，针对提供商的保护不适用，而且你的联系人会看到你的互联网地址（见第 7 章）。

### 当你的对方离线时会发生什么？

1. Cleona 同时启动所有合适的路径：在同一个 Wi-Fi 中直连，在互联网中经由两个邻居——以及额外的信箱。
2. 对于信箱，Cleona 会把加密消息存放在三个邻居处。一旦其中两个确认收到，就算作已存放。
3. Cleona 为此优先选择你的对方也会去查看的邻居——首先是他的邀请所提到的那位邻居。
4. 消息在那里等待最多 7 天。当你的对方回来，他会取走它并向你确认收到。只有这时你才会看到两个勾。

信箱只能由你的对方清空：取走和删除只能用一把只有他拥有的密钥进行，而且只有在他确认收到之后才会删除。邻居看到的只是某个每天都会变化的值之下的加密数据包。

### 陌生人进不来

对于既不是你的联系人、也不是共同群组成员的人，Cleona 只接受两样东西：对你公钥的询问（只要你有邀请仍处于开放状态），以及一个联系人请求。该请求必须携带你的一份有效邀请，且发送者必须事先解开一道计算题。其他一切——消息、通话、文件——在到达应用之前就被丢弃。因此只拿着你印制好的名片的人，无法直接呼叫你。共同群组的成员只能在这个群组中联系你——通过群组消息和群组通话，永远不会单独联系。

### 反审查

Cleona 的构造使其难以被封锁：

- **没有服务器，没有固定地址。** 应用里没有可被封锁的地址，网络也不依赖于任何单个节点。
- **没有固定端口。** 每台设备在首次启动时选择一个随机端口。没有已知的端口号可供识别 Cleona 流量。
- **如同随机数据。** 两台设备之间的连接建立被编码得与随机数据无法区分。
- **众多入口。** 每份邀请、每个邻居和同一 Wi-Fi 中的每台设备都是回到网络的一条可能路径。

### 安全的密钥存储

在受支持的平台上，Cleona 把你的加密密钥存储在操作系统的安全密钥环中（Android Keystore、iOS Keychain、macOS Keychain）。在可用之处，这为你的密钥提供硬件支持的保护。

### 数据库加密

你的消息和对话存放在一个加密数据库中——每个身份一个独立的数据库，每个都有自己的密钥。不仅数据库本身被加密，它的临时文件也是如此；没有任何东西会以未加密形式写到磁盘上，哪怕是短暂的一刻。设置、联系人和媒体也加密存储。

密钥从你的 24 个单词派生，只存在于你的设备上。即使有人拿到你的设备并读出数据，没有这些密钥也只会找到不可读的数据。

只有在你亲自把内容从 Cleona 中导出的地方，它才会是未加密的：
- 当你把一个文件从聊天保存到你的设备上时，
- 当你用截图按钮把一张图片存入你的图片库时，
- 当你把某个内容分享到另一个应用时，
- 当你设置媒体归档时（第 13 章）：归档的原件会以未加密形式存放在你家里的网络存储上，这样你即使不通过 Cleona 也能在那里打开它们，
- 当你把日程镜像到 Android 系统日历时：其他有日历访问权限的应用可以在那里读取它们。

这样导出的内容不会随消息一起删除，也不会随之过期。

### 屏幕上的保护

在 Android、Windows 和 macOS 上，Cleona 不允许其他应用进行屏幕录制。如果你需要一张图片，请使用顶部栏中的截图按钮：它会将图片存入你的图片库——未加密。在禁止转发的对话中，无法截图。

## 15. 软件更新

### 我如何获得更新？

Cleona 可以通过多种途径更新。目标是即便个别分发渠道失效或被封禁，你也能获得更新：

1. **App Store / Play Store：** 一旦 Cleona 出现在那里并且你通过商店安装了它，你就会像往常一样通过商店获得更新。在 iPhone 上，更新通过 TestFlight 提供。
2. **GitHub Releases：** 在项目的 GitHub 页面上你可以找到所有平台的已签名安装包。
3. **通过网络更新：** Cleona 可以直接通过网络获取更新——无需下载服务器。新版本被拆分成带纠错码的片段，分布到网络中；其中一部分甚至随掩护流量一起传输。你的设备收集足够的片段并组装出更新。传输的通常只是变更部分——几 MB，而不是整个应用。这适用于 Linux、Windows 和 Android；在 macOS 上，你从网站或 GitHub 下载新版本。
4. **邀请链接：** 你可以创建邀请链接，其中包含一位新用户安装 Cleona 并连接到网络所需的一切。
5. **物理传输：** 在没有互联网的环境中，你可以通过 USB 优盘或本地网络把 Cleona 传给别人。

### 更新如何进行

1. Cleona 在后台自动收集一次新更新的片段并组装它们。
2. 只有当更新**完整**且其**签名已验证**之后，Cleona 才会向你提供它。因此你永远不会被提供半成品或未经验证的更新。
3. 一旦你点击"安装"，安装会无需进一步确认就开始。在 Android 上系统还会额外显示其安装对话框。

不会提供较旧的版本——更新永远只能向前走。如果某个版本太旧以至于无法再与网络协作，Cleona 会明确指出这一点并请你更新。

### 签名验证

每次更新都经过双重签名：用一种经典方法和一种后量子方法。Cleona 自动验证两份签名。这样就确保只有来自官方开发者的更新会被接受——即使更新是经由网络从陌生设备而来的。更新永远不会自动从开发中产生，而只有在开发者手动签名时才会产生。

## 16. 常见问题

### "我可以在没有互联网的情况下使用 Cleona 吗？"

Cleona 需要网络连接，但不一定需要互联网：在同一个 Wi-Fi 中，Cleona 设备会自行互相发现，并可以在完全没有互联网接入的情况下互相通信。你也不必与你的对方同时在线：如果他离线，消息会在三个邻居处的信箱中等待最多 7 天，直到他取走。

### "如果我丢了助记词怎么办？"

只要还有一台设备运行着你的身份，就没有什么丢失——你直接在那台上继续写就行。在创建身份的那台设备上，你通常还可以重新查看那 24 个单词（见第 2 章）。但不要依赖这一点：重新安装会清掉这份副本，在 Android 上，移除或更改屏幕锁定也会将其销毁。如果你既没有这些单词，也没有任何设备，就没有回头路——通过你的联系人、开发者或任何其他人都无法恢复。因此把 24 个单词妥善保管才如此重要。

### "有人能偷看我的消息吗？"

不能。每条消息都用一把一次性密钥加密，该密钥只对这一条消息有效。只有你和你的对方能解密该消息。没有中央服务器，没有万能密钥，开发者也没有任何访问权限。即使一台设备在传输途中转发了该消息，它看到的也只是加密的杂乱数据和一个代码。你的邻居知道数据包来自你，但不知道它发给谁；你对方的邻居知道它发给谁，但不知道来自谁。

### "为什么我不需要电话号码？"

因为你的身份纯粹是密码学的。不是用一个与你的真实姓名关联的电话号码或电子邮箱，而是用一对在你的设备上生成的密钥来标识你。你通过二维码、NFC 或你邀请的文本行来添加联系人——而不是通过电话簿。这意味着更多隐私，因为你的 messenger 账户不与你的真实身份绑定。

### "我怎么在 Cleona 上找人？"

Cleona 有意不提供按电话号码或姓名查找联系人的功能——那会是个隐私问题。取而代之的是你直接交换邀请：通过二维码、NFC，或作为文本行经由其他途径。这就像交换名片，而不是在电话簿里查阅。

### "Cleona 在国外也能用吗？"

能。只要你有一根互联网连接，Cleona 在全世界都能用。由于没有中央服务器也没有固定地址，该服务无法简单地为某些国家而关闭。Cleona 如何使封锁更难，见"安全"一章中的"反审查"。不过，一个在边境拦截所有未知流量的国家，也能挡住 Cleona。

### "Cleona 免费吗？"

免费。Cleona 可免费且无广告地使用。由于没有中央服务器，运行也不会产生服务器成本。在设置中的"支持 Cleona"→"捐赠"下，你可以自愿支持开发。

### "我的消息只有一个勾——这是什么意思？"

消息在途中，但你的对方尚未确认收到——多半因为他刚好离线。这不是错误：消息会在信箱中等待最多 7 天。他一取走，你就会看到两个勾。一个时钟表示还没有任何路径承载过这条消息——一旦有路径可用它就会自动发出；一个警告标记表示它已连续 14 天没有找到路径，你可以重新发送它。

### "为什么消息在我的 iPhone 上会延迟到达？"

iOS 不允许应用在后台持续运行。Cleona 只会被偶尔短暂唤醒；何时唤醒由 iOS 决定。它随后会取回全部内容。你一打开应用，Cleona 就会取回为你保存的内容。

### "我可以从 WhatsApp 切换到 Cleona 吗？"

可以，但你无法迁移你的 WhatsApp 聊天。Cleona 和 WhatsApp 是根本不同的系统。你必须在 Cleona 中逐个添加你的联系人。最简单的办法是把你的邀请文本行发给你的联系人。每条这样到达的请求都由你在"请求"下自行确认。

### "我可以同时在多台设备上使用 Cleona 吗？"

还不行。用于同一身份的第二台设备将在后续版本中提供（第 11 章）。如今你可以在多台设备上使用不同的身份。

### "当 App Store 被封禁时，我如何获得更新？"

Cleona 可以直接通过网络获取更新，而不依赖应用商店、网站或下载服务器。如果网络中另一台设备拥有最新版本，你的设备可以从那里加载更新。真实性通过开发者的数字签名来验证。或者，一位联系人可以通过邀请链接或 USB 优盘把应用传给你。更多内容见"软件更新"一章。
